# Contributing

Run `uv sync --frozen` and install frontend dependencies with `npm ci` in `web`. Use Python and Node versions declared by the workspace and frontend package. Run `make quality`, `make test` and `make claims` before proposing changes.

Change document templates rather than generated README, results or readouts. Numerical claims must originate in stored records. A new gate needs a clean pass, deliberate failure and empty-input refusal. A persistence change needs an observer outside the writing session. Statistical changes need known-truth empirical validation with declared Monte Carlo tolerance; do not tune seeds or generating parameters to make a failed result disappear.

Simulation changes must identify source, seed and assumptions. Do not add a production claim, fabricated company experiment, uncorrected exploratory verdict or metric display preceding health checks. Forbidden long-dash punctuation is checked across code, documents, templates and chart strings.

Commit changes conventionally in coherent units. Keep uploaded private data and tokens outside version control. The checked-in public dataset retains its separate provenance and license status.
